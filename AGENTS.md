# YouTube Localizer

- Standalone MV3 Chromium and Firefox extension. No OpenPost API, Google OAuth, telemetry, remote code or operator backend.
- Run `npm ci`, `npm run verify`, and `npm run package` in the project Devenv environment. Browser tests use isolated profiles and intercepted Studio/provider responses, never real accounts or keys.
- `src/studio` owns DOM discovery and tightly scoped translation-dialog writes. Never alter visibility, scheduling, audio, subtitles or deletion. Read unknown data as unknown, never empty. Support English Studio first and stop with instructions on unsupported UI rather than guessing labels.
- Bind Studio work to a discovered channel/tab and observed authuser. Preserve that selector on navigation and verification links. Replace closed tabs only; changed or unreadable existing tabs require reconnection. Account bindings never enter backups.
- `src/layers` owns one paid Layerize preparation per source hash and local canvas composition. Recheck the pause epoch immediately before preparation POSTs. Sanitize static overlays in the bundled offscreen document, use local fonts, bundle the same authored fonts in previews and offscreen composition independently of UI theme fonts, and record template revisions on rendered slots. Approval and application must match the current approved revision. Local renders never consume paid request quota.
- `src/thumbnails` owns original-image creation and saved reference snapshots. References remain in extension IndexedDB until selected for an explicit Generate action. Persist creation IDs before paid requests, recheck pause immediately before Fal POSTs after reference serialization, and persist queue receipts before polling. Original-image creation uses the selected Fal model independently of localization mode. Studio content can open the composer but cannot generate, read references or access keys. Generated thumbnails may be downloaded or chosen as cached localization sources; primary-thumbnail Studio writes remain outside scope.
- `src/core` owns durable jobs and missing-only plans. Store component source hashes and generated assets before application. Recheck Studio before writes. Image verification remains uncertain unless Studio exposes sufficient evidence.
- `src/providers` owns paid network requests. GPT Image 2.5 Sunburst is the default image editor. All image requests use Fal, including GPT Image. Persist submitting before requests and Fal receipts before polling; resume receipt retrieval after worker restarts. Never automatically retry an ambiguous submission. Credentials belong only to trusted extension contexts; never content messages, logs, exports or sync storage.
- Service-worker runs advance through persisted checkpoints. Use a single Web Lock for coordinator work and a separate durable pause epoch checked before paid requests and before Studio mutations.
- External data and messages require schema validation. Imported history is a cache and must lose approval/verification authority. ZIP archives exclude credentials and remote URLs. Validate language identifiers before using them in archive filenames.
- Consult PRODUCT.md, DESIGN.md and docs/ui-brief.md for UI scope and tokens. Keep OpenPost's CTA in About/onboarding. Main views should have one next action and no repeated explanatory paragraphs; put advanced settings behind disclosures.
- `docs/pilot.md` owns the live scheduled-video acceptance gate. Fixture tests do not prove live application.

- UI views use Svelte 5 and Vite static entries. `@openpost/ui` owns controls, themes, icons and shared CSS. Keep the Dither family fixed; follow system light/dark appearance without a theme picker. Use namespaced extension CSS aliases so runtime theme variables cannot overwrite them. Form submit buttons need an explicit type="submit"; the shared Button defaults to type="button". Save success and failures use the shared toaster.
- `vendor/` contains compiled, versioned UI and Dither package archives from OpenPost. Update both archives and the npm lockfile together; `npm ci` must work without an OpenPost checkout. Shared UI changes belong in OpenPost’s `packages/ui`, never a copied extension component.

- Promise APIs go through `platform/webextension.ts`, selecting native Firefox browser or Chromium chrome. Firefox uses an event background page for DOM rendering and a sidebar. Persistent Firefox credentials use a separate extension-origin IndexedDB vault because local storage has no trusted-context access restriction; the vault never enters backups.

- Text credentials carry their saved base URL. Reject a different endpoint before sending a key. OpenRouter is an OpenAI-compatible preset; custom URL and model fields belong in Connection. Older direct OpenAI image settings migrate to the equivalent Fal model, while cached assets and legacy creation history remain readable.
